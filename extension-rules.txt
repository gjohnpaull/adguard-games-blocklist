! ==========================================================================
! THESE RULES DO NOT GO IN ADGUARD HOME.
! ==========================================================================
! AdGuard Home filters DNS. DNS carries a hostname and nothing else - no path,
! no query string. Rules below need a filter that sees the full URL and the
! page DOM, which means:
!   - AdGuard browser extension, or
!   - AdGuard for Windows / Mac (desktop app, HTTPS filtering on)
! Paste into: Settings -> Filters -> Custom -> add your own rule.
!
! Verified against a live google.com/search?q=games page on 2026-09-10.
! ==========================================================================

! --- RECOMMENDED: hide the "Games from Google" carousel -------------------
! Removes the inline playable games (Snake, Solitaire, Minesweeper, PAC-MAN,
! Baseball, Block Breaker, Garden Gnomes, Color Tiles, Popcorn, Tic-Tac-Go,
! Champion Island) from search results WITHOUT breaking search.
!
! Measured: removed 285px containing all game tiles; all 9 organic results
! survived. Matches exactly one element on the page.
!
! Targets the heading TEXT, not Google's class names - those are obfuscated
! (cgj45, MFaqpc, yp1CPe) and rotate, so a class-based rule would rot.
! Works on ANY query that surfaces the carousel, not just "games".
www.google.com#?#div:has(> div > h2:contains(Games from Google))

! Non-English Google uses translated headings, so add your locale's wording.
! Find it by searching "games" on your local Google and reading the heading.
! Example shape:
! www.google.de#?#div:has(> div > h2:contains(Spiele von Google))

! --- OPTIONAL: block the games by direct URL ------------------------------
! The carousel games are also reachable by navigating straight to them, which
! a cosmetic rule cannot stop. These block the game endpoints themselves.
||google.com/fbx*$document
||google.com/logos/fnbx/*

! --- BLOCK THE SEARCH URL ITSELF ---------------------------------------
! Requested explicitly. Syntax verified against
! https://adguard.com/kb/general/ad-filtering/create-own-filters/ :
!   "|"         = "pointer to the beginning ... of address"
!   "$document" = "explicitly enables blocking of main frame document
!                  requests" (without it, page navigations are not blocked)
!   "*"         = "any set of characters ... can also be an empty string"
!
! NOT executed against a live AdGuard install - none is present on this
! machine. Syntax is doc-verified; matching behaviour is reasoned from the
! documented semantics above.

! 1. Literal prefix, exactly as asked.
|https://www.google.com/search?q=games$document

! 2. Recommended instead of #1. Handles the cases #1 misses: non-www,
!    and a query where q= is not the first parameter (Google reorders these).
!    Real observed URL: /search?q=games&num=10&sca_esv=... - #1 catches that
!    one, but /search?sca_esv=...&q=games would slip past it. "*" matching an
!    empty string means this covers both.
||google.com/search?*q=games$document

! 3. Your regional Google. Chrome sends searches to the local domain, so
!    without this the .com rules are trivially sidestepped.
||google.ae/search?*q=games$document

! 4. Precise variant. Rules 1-3 match by prefix, so they ALSO block
!    q=gamestop, q=games2 and q=gamespot. This regex requires "games" to be
!    the whole value. Use INSTEAD of 1-3 if that over-blocking bothers you.
! /^https?:\/\/(www\.)?google\.[a-z.]+\/search\?.*[?&]q=games(&|$)/$document

! Known limits of all of the above, stated plainly:
!   - "gaming", "play games", "free games" are different queries and pass.
!   - Bing, DuckDuckGo, Yahoo and image search are untouched.
!   - This is why the cosmetic carousel rule above is the better lever: it
!     fires on any query that surfaces the games, not one exact string.
